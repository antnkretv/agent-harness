# Вычитка текста

Требования - [стандарт текста](../../../docs/platform/standards/text.md), комментарии в коде -
[code-comments](../../../docs/platform/standards/code-comments.md) (XML-doc и JSDoc - скилл
[code-docs](../code-docs/SKILL.md)), структура документации -
[documentation](../../../docs/platform/standards/documentation.md). Ошибки во всех стеках
проверяются по разделу "Ошибки" общего стандарта, основанному на Microsoft Error Message Guidelines.

1. Определи адресата и действие, которому помогает текст. Найди места формирования и вывода.
2. Сверь каждую причину и последствие с данными и кодом. Удали неподтвержденные утверждения.
3. Для issue, PR, коммита, ревью или ответа агента примени подразделы "Задачи, изменения и ответы
   агента" и "Язык описаний, задач и комментариев" стандарта.
4. Удали текст без полезного факта. Сохрани объяснение причины и последствия; сырые протоколы
   вынеси по ссылке или в раскрываемый блок после вывода.
5. Отредактируй оставшееся по стандарту. Сохрани ключи, аргументы, плейсхолдеры и служебные маркеры.
6. Проверь итоговое сообщение после подстановок: отдельные строки реестра могут составлять повтор.
7. Перечитай текст без истории сессии по последнему абзацу того же раздела стандарта.
8. Запусти Vale и проверку ссылок. Смысловые требования, которые Vale не проверяет, сверь вручную.

```bash
./.harness/hooks/python.cmd .harness/scripts/check/vale-lint.py --worktree
./.harness/hooks/python.cmd .harness/scripts/check/vale-lint.py --files <пути>
./.harness/hooks/python.cmd .harness/scripts/check/check-docs.py --area docs --anchors
```

Исключения для машинных и вендорных файлов задаются манифестом проекта. Выводимый человеку текст
проверяется независимо от того, из какого технического каталога его читает программа.
