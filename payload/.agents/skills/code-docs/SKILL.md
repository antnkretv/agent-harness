# Документирующие комментарии

Требования - раздел 5 [стандарта комментариев](../../../docs/platform/standards/code-comments.md#5-документирующий-комментарий),
язык - [стандарт текста](../../../docs/platform/standards/text.md), термины - [глоссарий](../../../docs/platform/standards/product-terms.md).

1. Прочитай реализацию элемента и его вызывающих. Комментарий пишется по коду головы ветки, а не по
   имени, прежнему тексту или замыслу.
2. Выпиши, что читатель подсказки IDE не выведет из имени и сигнатуры: границы диапазона, условия
   `null`, `false` и пустого результата, исключения, побочный эффект, единицы, причину ограничения.
   Пустой список - комментарий удаляется или не пишется.
3. Проверь каждый пункт по коду: границу - по оператору сравнения, `null` - по каждой ветке возврата,
   причину - по коду, документу или задаче. Неподтвержденный пункт не пишется.
4. Разложи пункты по тегам: `<summary>` - что делает элемент, `<remarks>` - почему, `<param>` и
   `<returns>` - только сведения сверх имени. В JSDoc и TSDoc - описание, `@remarks`, `@param`, `@returns`.
5. Значение константы и настройки замени ссылкой `<see cref="..."/>` или `{@link ...}`.
6. Перечитай текст как подсказку без кода: полные предложения, глагол операции, термины глоссария.
   Образ, просторечие и пересказ имени удали.
7. Запусти гейт комментариев и Vale по измененным файлам.

```bash
./.harness/hooks/python.cmd .harness/scripts/check/check-comments.py --files <пути>
./.harness/hooks/python.cmd .harness/scripts/check/vale-lint.py --files <пути>
```

Превышение порога объема не повод сжимать текст в намек: удали пункты, которые не помогают
вызывающему, или вынеси обоснование в документ по ссылке.
