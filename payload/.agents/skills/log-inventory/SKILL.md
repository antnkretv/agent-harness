# Инвентаризация сообщений

Правила необходимости и уровня - раздел ["Необходимость и уровень сообщения"](../../../docs/platform/standards/text.md#необходимость-и-уровень-сообщения)
стандарта текста, формулировки - остальные его разделы, место реестра -
[реестры текста](../../../docs/platform/architecture/gates.md#реестры-текста). Скилл задает только
порядок разбора; правило, которого нет в стандарте, сначала дописывается туда.

## Выгрузка

```bash
./.harness/hooks/python.cmd .harness/scripts/text/message-inventory.py --path <корень> --summary
./.harness/hooks/python.cmd .harness/scripts/text/message-inventory.py --path <корень> > <таблица>.tsv
```

Строка таблицы - одно сообщение. `level` - объявленный уровень: у журнала его дает `[LoggerMessage]`,
у скрипта - определение хелпера вызова по колонке "Вывод скрипта" таблицы уровней стандарта. `expected` - уровень, который предсказывают признаки места вызова.
`where` - строка реестра и первый вызов. Без `--path` выгрузка идет по всем реестрам дерева.

| `tier` | Значение |
| --- | --- |
| `A`, `B` | Предложенная группа необходимости |
| `C` | Кандидат в шум |
| `U` | Текст для пользователя: проверяются потребитель и повтор |
| `-` | Часть другого сообщения: подпись, заголовок колонки, подстановка |
| `!` после `U` и `-` | Ключ без потребителя или повтор |

Предложение таблицы - не вердикт: группу решает чтение места вызова по вопросам стандарта.

## Признаки

| Признак | Что найдено | Что проверить |
| --- | --- | --- |
| `unused` | Вызова ключа нет | Динамический ключ, plural-формы, построитель ключей, `msg_bundle`; без потребителя ключ удаляется. Свой детектор неиспользуемых ключей приложения точнее признака: решает его вывод |
| `dynamic` | Ключ собирается из частей | Построитель ключа вручную |
| `duplicate` | Тот же шаблон у другого ключа того же реестра; словари интерфейса признак не получают: одна подпись в разных разделах не доказывает общий смысл | Один ключ, вызовы переводятся на него; повтор в словаре проверяет детектор приложения |
| `verbose` | Строка выводится только с подробным выводом или уровнем Debug и Trace | Группа A - уровень поднимается, иначе строка удаляется с вызовом |
| `loop` | Строка уровня Information внутри цикла | Свести к итогу этапа или к метрике |
| `no-data` | Строка Information без подстановок | Итог без чисел - шум; граница этапа получает числа или удаляется |
| `level-low` | Слова отказа или обработчик исключения при уровне Information | Уровень по таблице стандарта или текст без ложного отказа |
| `level-high` | Слова успеха при Warning вне обработчика | Понизить уровень |
| `no-exception` | Error журнала без исключения вне обработчика | Передать исключение или пересмотреть уровень |

Ожидаемый уровень выводится признаками, которыми исследования выбора уровня предсказывают его по
коду: блок вызова (обработчик исключения, ветка отказа, цикл), слова шаблона и хелпер вызова. У Li
и др. сильнейшие признаки - блок вокруг вызова и текст записи, а точность модели (AUC от 0,75 до
0,81) недостаточна для автоматической правки. Поэтому `level-low` и `level-high` - повод перечитать
вызов, а не правка.

## Порядок

1. Выгрузи корень и получи счет групп и признаков.
2. Сними `unused` и `duplicate`, сверив потребителей по таблице признаков.
3. Прочитай в месте вызова каждую строку `C`, `verbose`, `loop` и `no-data`, реши группу по вопросам
   стандарта. Шум удаляется вместе с вызовом; хелпер, оставшийся без вызовов, удаляется тоже.
4. Реши расхождения `level-low`, `level-high` и `no-exception` по таблице уровней стандарта.
5. Строку, где группа или уровень остались спорными, разбирает второй агент без твоего вывода.
   Расхождение двух разборов решает человек; PR называет такие строки.
6. Запусти гейты реестров и области скриптов:

```bash
./.harness/hooks/python.cmd .harness/scripts/check/check-text-registry.py
./.harness/hooks/python.cmd .harness/scripts/check/vale-lint.py --worktree
```

PR перечисляет снятые и измененные сообщения по признакам и называет причину каждой группы правок.

## Объем в работе

Таблица считает статически. Объем строк в работе дают шаблоны журнала: группировка по `EventId` или
шаблонам хранилища журналов за неделю показывает частые строки - кандидатов в `loop` и шум, - и строки без
единого вхождения.

  [сравнение LLM в выборе уровня](https://arxiv.org/abs/2410.08499) (2024).
- Шаблоны частых строк: He и др., "Drain: An Online Log Parsing Approach with Fixed Depth Tree" (ICWS, 2017).
