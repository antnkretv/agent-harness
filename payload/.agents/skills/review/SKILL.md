# Ревью

В проекте используй этот skill вместо личных `review` и `review-agent`.
Если получен промпт отдельного прохода, выполни только его: новый круг не запускай.

1. Определи PR по регистрации текущей ветки или PR этой ветки. Если PR нет или выбор
   неоднозначен, уточни цель; не создавай PR и не выбирай другой вид ревью самостоятельно.
2. Обнови сведения о PR и базе. Работай на его head. При незакоммиченных или невыложенных
   изменениях остановись и назови препятствие.
3. Проверь прошлые вердикты: проход с апрувом закрыт. Если апрув удаленного круга есть у каждого
   обязательного прохода и на текущей голове есть статусы `review/<проход>`, верни итоги и
   завершись. Нет статусов - запроси круг: он перенесет апрувы на голову, проходы не исполняя.
   Апрув локального круга удаленный план не засчитывает
   ([`ci-cd.md`](../../../docs/platform/delivery/ci-cd.md#локальный-круг-ревью)).
   Если круг уже идет на этих входах, наблюдай его.
4. Получи актуальный план: `./.harness/hooks/python.cmd .harness/scripts/pipeline/pipeline-run.py plan change`.
   Выполни необходимые стадии по ссылкам `doc` из этого плана.

Перед запуском круга сверь с текущим diff заголовок и тело PR, комментарии, которые PR добавил
или тронул, и правленые им документы. Утверждение, которого код не держит, правится здесь. Требования к формулировкам -
[стандарт текста](../../../docs/platform/standards/text.md).

Запроси круг командой, которую называет шаг `review` конвейера: запрос мимо гейта конвейер не видит.
Параметры запуска, состав проходов и ссылки на их инструкции находятся в
`processes.review` методологии и в выводе плана. Разбор архитектуры ведет skill
[`architecture-review`](../architecture-review/SKILL.md).

Не имитируй эти проходы чтением файлов в авторской сессии. Вердикт себе авторская сессия не пишет.

**Круг идет на неподвижной голове.** Метка ставится на коммит, который остается головой до
вердиктов. Круг автоправки бота проходит до метки, а не рядом с ней. Понадобилась правка - дождись
вердиктов и возьми её следующим кругом.

**Апрув прохода постоянен** ([`ci-cd.md`](../../../docs/platform/delivery/ci-cd.md#бюджет-кругов)): новый
круг поднимает только проходы без апрува; коммиты после апрува всех проходов сверх
[правки после апрува](../../../docs/platform/delivery/ci-cd.md#правка-после-апрува) поднимают все проходы. Реестр прошлых решений сохраняет историю обсуждения, но
не дает одобрения. Исчерпанный бюджет и `blocked` одобрением не считаются.

**Порядок при круге без вердикта.** Величины печатает
`./.harness/hooks/python.cmd .harness/scripts/check/check-pipeline.py --emit-fallback`, в skill они не повторяются.

1. Жди вердиктов не дольше `waitMinutes` так, как называет шаг
   ([сессия конвейера](../../../.harness/README.md#сессия-конвейера)). Молчание сверх срока
   считается кругом без вердикта.
2. Прочитай строку, которую конвейер оставил на PR: она называет проход и причину. Метку из поля
   `processes.review.failedLabel` не снимай, её снимает следующий круг. Строки нет вовсе - причина в журнале
   прогона, а круг мог не стартовать.
3. Отказ среды или молчаливый проход - повтори запрос круга, не больше чем `retries`
   раз. Подтвержденный отказ авторизации, отозванный токен или недоступность исполнителя круга -
   сразу к локальному кругу. Бюджет кругов повтор не тратит:
   он считается по вердиктам.
4. Повторы кончились, круг снят по таймауту задания или раннеры не отвечают - поднимай локальный
   круг ([`ci-cd.md`](../../../docs/platform/delivery/ci-cd.md#локальный-круг-ревью)).
5. Вердикты локального круга публикуй флагом `--publish` скрипта круга
   ([`ci-cd.md`](../../../docs/platform/delivery/ci-cd.md#локальный-круг-ревью)). Готовность считается по
   [`issue-dev`, ready](../issue-dev/SKILL.md#ready).

Локальный круг выполняют независимые агенты провайдера авторской сессии. Модель прохода называет
шаг круга: модель комплекта для провайдера сессии, для провайдера вне комплекта - модель сессии;
усилие не наследуется. Круг разбирает закоммиченную голову ветки PR, совпавшую с
origin: скрипт отказывает, если рабочая копия не на ветке, разошлась с origin или origin не ответил.
Перед кругом закоммить и запушь правки.

1. Подготовь пакет скриптом `processes.review.fallback.runner`: `--pr`, `--reason <ключ>`, `--provider` и
   файл постановки через `--context`. Ключ причины - из записи `LocalReason` реестра
   [`variables.json`](../../../.harness/templates/variables.json): неизвестный ключ скрипт отклоняет.
2. По `round.json` запусти отдельного агента с новым контекстом на каждый проход. Передай только
   его промпт и пути пакета, без истории разработки и авторского аудита; в сессии без человека
   передай и ограничения команд из общего промпта исполнителя, если он их задает. Постановка - только для `context: true`.
   Агенты читают закрепленное дерево, не правят и не публикуют; голову до ответов не меняй.
3. Сохрани ответы дословно в `response`-файлы, а журнал сессии агента прохода в формате провайдера -
   в `journal`-файл: прочитанное круг берет только из журнала. Вызови скрипт с `--pr`, `--collect` и `--work`
   без `--publish`. Ответ, который сбор отклонил, - длиннее `processes.review.bodyChars`, не по-русски, не
   по схеме, - передай тому же агенту прохода с текстом отказа и собери заново. Когда сбор принял все
   ответы, повтори вызов с `--publish` и сверь условия готовности из `processes.merge.steps`.

Если провайдер сессии не может запустить независимый проход, запусти круг тем же скриптом с
`--pr`, `--reason`, `--context`, `--provider` этого провайдера, `--execute` и `--publish` ([исполнитель](../../../docs/platform/delivery/ci-cd.md#локальный-круг-ревью)).
Исполнителя скрипт выбирает по [порядку владельца](../../../docs/platform/delivery/ci-cd.md#локальный-круг-ревью)
и публикует вердикты. Нет исполнителя - назови
отказ и оставь PR в Draft.

## Ответ

В ответе укажи PR, тип круга, итоги проходов и незакрытые блокировки: заполни слоты заготовки
`./.harness/hooks/python.cmd .harness/scripts/text/text_templates.py form ReviewReport --out <файл>` и собери ответ командой
`./.harness/hooks/python.cmd .harness/scripts/text/text_templates.py render report/review --set-file ReviewReport=<файл> --change <PR>`. Сам вызов ревью не переводит PR в Ready.
