# Правила агентов harness

Единая инструкция комплекта для всех ИИ-агентов в репозитории; `AGENTS.md` проекта добавляет правила проекта. Локальные `AGENTS.md`, `CLAUDE.md`, `REVIEW.md`, rules и skills внутри приложений не создаются.

- Документация проекта - [`docs/README.md`](../docs/README.md), документы harness - [`.harness/docs/README.md`](docs/README.md), конвейер - [`.harness/README.md`](README.md).
- Git, ветки, коммиты и PR - [`.harness/CONTRIBUTING.md`](CONTRIBUTING.md); ревью - [`.harness/REVIEW.md`](REVIEW.md); ревью PR, упрощение и Ready агент выполняет только шагами [`issue-dev`](../.agents/skills/issue-dev/SKILL.md).
- Skills - [`.harness/docs/skills.md`](docs/skills.md) и [`.agents/skills/README.md`](../.agents/skills/README.md) проекта: `SKILL.md` релевантной задачи читается целиком. SDD - [`sdd.md`](docs/sdd.md), треки - [`specs/README.md`](../specs/README.md).

## Обязательные правила

- Issue, PR, коммиты, комментарии, ревью и ответы агента пиши для человека без истории сессии:
  проблема, изменение, основание вывода и оставшаяся работа - по [стандарту текста](../docs/platform/standards/text.md#задачи-изменения-и-ответы-агента).
- Стейджить только явные пути: без `git add -A`, `git add .` и посторонних изменений.
- Ноль комментариев и ноль новых тестов - нормальный результат: [`code-comments.md`](../docs/platform/standards/code-comments.md), [`test-usefulness.md`](../docs/platform/standards/test-usefulness.md).
- Legacy-код не остается: целевая архитектура сразу, все потребители переведены ([§10](CONTRIBUTING.md#10-находки-по-пути)); публичный контракт проверяется с ними, границы держат [гейты стека](../docs/platform/architecture/gates.md).
- Требования трассируются в spec, task, issue, commit и PR. Меток `FR-NNN` и `NFR-NNN` в комментариях кода нет: [`code-comments.md` §7](../docs/platform/standards/code-comments.md#7-что-не-пишут-в-комментарии).
- Перед расследованием CI, инцидента или производительности обновить сведения о базовой ветке и PR. При событии открытого PR работать на его head или в stacked PR с base на этот head.
- По прямому поручению человека субагенты реализуют непересекающиеся области, координатор пишет постановку исполнителю по [шаблону](docs/delegated-task.md) и проверяет ветку целиком; без поручения веер - только разведка. Навигация по коду - через LSP, если он подключен.
- {{#if setting:agents.pushback=full}}Каждое утверждение постановщика задачи проверяется, а не принимается на веру: агент называет пробелы и спорные места в архитектуре, требованиях, производительности и сложности кода (KISS) и предлагает лучшее решение.{{/if}}{{#if setting:agents.pushback=critical}}Агент оспаривает постановку только в критичных местах: отклонение от архитектуры, требований или логики.{{/if}}{{#unless setting:agents.pushback=none}} Уточнение запрашивается один раз: выбор человека закрывает вопрос.{{else}}Агент не спорит с постановкой и делает, как сказал человек.{{/unless}}
- Правило репозитория снимается правкой правила, а не доводом в задаче; намеренное расхождение - в PR.
- {{#if setting:agents.findings=same-pr}}Попутная находка чинится в текущем PR, даже не по теме задачи, если человек не попросил ее отложить; описание правку не заменяет{{else}}Попутная находка вне постановки идет по политике `agents.findings`; дефект, внесенный самим PR, и принятый совет ревью чинятся в нем{{/if}}: [`.harness/CONTRIBUTING.md` §4](CONTRIBUTING.md#4-коммиты-ии-агентов) и [§10](CONTRIBUTING.md#10-находки-по-пути).
