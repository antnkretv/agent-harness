# Термины harness

> **Тип (Diataxis):** Справочник

Словарь понятий, которыми пользуются правила, промпты и сообщения harness. Когда термин уместен в
тексте для человека, задает [стандарт текста](../../docs/platform/standards/text.md); термины продукта проекта - в
[глоссарии проекта](../../docs/platform/standards/product-terms.md).

## Работа с кодом

| Термин | Значение |
| --- | --- |
| Запрос на слияние, запрос | Pull request у GitHub или merge request у GitLab |
| Поставщик кода | Площадка, где лежит репозиторий и идут запросы: GitHub или GitLab; модуль `forge` |
| Трекер | Система задач: GitHub Issues или Jira; модуль `tracker` |
| База | Ветка, в которую вливается запрос, и ее коммит, против которого строится дифф |
| Голова запроса | Последний коммит ветки запроса. Проверки относятся к конкретной голове: новый коммит требует новых результатов; апрув прохода ревью постоянен |
| Подлив базы | Слияние актуальной базы в ветку запроса, стадия `sync-base` |
| Попутная находка | Ошибка вне постановки, найденная по ходу работы. Что с ней делать, задает настройка `agents.findings` и [CONTRIBUTING.md](../CONTRIBUTING.md#10-находки-по-пути) |
| Веер | Параллельный запуск нескольких субагентов на одну задачу |

## Процесс

| Термин | Значение |
| --- | --- |
| Процесс | Именованная последовательность шагов в `processes` манифеста методологии: разработка, упрощение, проверка, ревью, мерж |
| Шаг | Одно действие процесса со своими предусловиями, результатом и инструкцией |
| Композиция | Порядок процессов для вида работы: `change` - обычный запрос, `release` - выпуск; `.harness/pipelines.json` |
| Стадия | Процесс или шаг композиции при исполнении `pipeline-run.py` |
| Подтверждение стадии | Запись `pipeline-run.py` о выполненной команде, аудите или действии на площадке. Подтверждение привязано к снимку и без него стадия не считается пройденной |
| Снимок | Отпечаток дерева рабочей копии, базы, постановки и правил, к которому привязано подтверждение стадии |
| Гейт | Механическая проверка дерева или текста, которая проходит или отказывает. Гейты идут в git-хуках и в шаге Check CI |

## Ревью

| Термин | Значение |
| --- | --- |
| Проход ревью | Разбор запроса одним исполнителем по своим критериям: код, требования и документация, архитектура |
| Круг ревью | Один запуск обязательных проходов на одной голове запроса |
| Критерии прохода, планка | Документ, по которому проход оценивает запрос: `REVIEW.md` и файлы `.harness/review/`. Читается из базы, поэтому запрос не меняет правила своего ревью |
| Вердикт | Итог прохода: `approve` - блокирующих находок нет, `changes` - есть блокирующая находка, `blocked` - разбор не состоялся |
| Бюджет кругов | Сколько вердиктов проход дает на одной голове, `processes.review.steps[].budget` |
| Порог застоя | Число кругов подряд с запросом правок, после которого конвейер предупреждает в запросе, что следующий круг стоит решить человеку, `processes.review.stallRounds` |
| Локальный круг | Резервный круг ревью независимыми агентами сессии автора, когда удаленный круг не дал вердикта |
| Страж круга | Задание CI, которое ждет все проходы и сообщает в запросе о круге без вердикта |
| Квитанция | Файл `log.receipt.json`: подтверждение, что сессия прохода шла на неизмененном дереве текущего запроса |
| Метка автора | Строка из `policies.authorship`, которой заканчивается комментарий агента у поставщика кода; по ней конвейер отличает его от комментария человека |

## Комплект

| Термин | Значение |
| --- | --- |
| Комплект | Архив agent-harness: правила, процессы, промпты и проверки, которые ставятся в проект |
| Установка | `ah.py apply`: перенос файлов комплекта в проект по ответам настройки |
| `lock.json` | `.harness/state/lock.json`: версия комплекта, манифест установки, включенные пути и роли файлов слоя |
| Управляемый файл, блок | Файл или участок между метками `harness:begin` и `harness:end`, который принадлежит комплекту и обновляется установкой |
| Правка проекта | Изменение файла или блока комплекта проектом; его отклоняет гейт `harness-files`, а следующий `apply` или `install` пишет файл версией комплекта, поэтому нужную правку проект держит в месте проекта ([harness.md](harness.md#правки-проекта-и-единообразие)) |
| Приемка установки | `verify` установщика из архива установленной версии: проверка манифеста, реестра правил, гейтов и отрицательных проб. Не путать с критериями приемки задачи |
