# Корневые инструкции репозитория

> **Тип (Diataxis):** Справочник

Все постоянные инструкции агентов принадлежат корню репозитория. Каталоги приложений, `docs/` и
прочие подкаталоги не содержат собственных `AGENTS.md`, `CLAUDE.md`, `REVIEW.md`, `CONTRIBUTING.md`,
rules, skills или subagents.

## Роли файлов

| Файл | Роль | Лимит |
| --- | --- | --- |
| `README.md` | вход для человека | 25 строк, 350 слов |
| `AGENTS.md` | общие правила и маршрутизация по областям | 60 строк, 900 слов |
| `CLAUDE.md` | только особенности Claude Code | 30 строк, 350 слов |
| `CONTRIBUTING.md` | git, ветки, PR, человеческий текст и принципы кода | без формального лимита |
| `REVIEW.md` | общая планка code review и требования к доказательству | 120 строк, 1300 слов |

Строка файла-инструкции не превышает 300 символов. Проверку выполняет
`.harness/scripts/check/check-docs.py --area docs`.

## Корневые каталоги агентских активов

| Каталог | Содержимое |
| --- | --- |
| `.agents/skills/` | skills и их references |
| `.agents/rules/` | правила агентов по путям; Claude Code и Cursor читают их через ссылки |
| `.claude/` | адаптеры и hooks Claude Code |
| `.cursor/` | адаптеры и hooks Cursor |
| `.codex/` | адаптеры Codex |
| `.harness/prompts/` | промпты проходов CI |
| `.harness/review/` | специализированные планки review |
| `.harness/hooks/` | общая реализация hooks |

Правило агента по путям - один файл в `.agents/rules/`: матчеры обоих агентов (`paths` и `globs`) на
одни пути и ссылка на корневой SoT. Содержательные правила в правило не копируются. В каталогах
агентов правила лежат только ссылками `harness-*` на этот файл. Общая реализация hook не
оборачивается скриптом внутри приложения. Правило не ссылается в каталог агента - ни в чужой, ни в
свой. Правила сверяет `.harness/scripts/check/check-docs.py --area agents` - по матчерам и целям
ссылок, а не по прозе.

## Содержание entry-файла

Владельцы тем - [карта ролей](../../docs/platform/standards/documentation.md#карта-ролей).

Entry-файл содержит только решение, которое агент должен принять до выбора тематического документа.
В таблице областей допускаются стабильные команды входа в проверку: имя команды приложения или
запуск его общего гейта. Их определения и версии принадлежат манифестам стека и CI. Составные
процедуры, версии, списки активных работ, история ошибок и объяснение происхождения правила
в entry-файле не хранятся.

При установке harness общая методология остается в управляемом блоке, особенности проекта -
в блоке project после него. Прежние общие правила сводятся с блоком при установке и обновлении. Гейт документации
отклоняет дословный повтор абзаца из 12 и более слов одновременно в блоке harness и в блоке project;
заголовки, списки, таблицы, цитаты и примеры кода этой проверкой не сравниваются.
