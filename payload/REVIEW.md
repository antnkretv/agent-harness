## Стандарт

Изменение принимается, когда оно улучшает состояние кода и не содержит блокирующих находок.
Совершенство не требуется. Технические факты, принятые правила и наблюдаемое поведение важнее
личного предпочтения.

Проверяется каждая измененная человеком строка, включая удаленные. Сгенерированные файлы
проверяются через их источник и контракт генерации.

## Вес

| Находка | Вес |
| --- | --- |
| Воспроизводимая ошибка поведения, данных, доступа, безопасности или контракта | блокирует |
| Нарушение исполняемого инварианта или принятого ADR | блокирует |
| Второй сценарий на то же правило, сценарий без бизнес-кейса или без правдоподобной регрессии прикладного кода; корпус анализаторов и самопроверки поставки судятся по их условиям в критерии полезности теста | блокирует |
| Требование добавить тест к правке, которая его не требует | в ревью не входит |
| Нарушение стандарта текста, меняющее понимание проблемы или необходимое действие | блокирует |
| Комментарий без цели из [стандарта комментариев](docs/platform/standards/code-comments.md#2-цель-комментария) или без цели, названной в PR | блокирует |
| Комментарий, пересказывающий код, имя или сигнатуру соседней строки | блокирует |
| Комментарий на языке механики там, где правило прикладное | советует |
| Снятая или ослабленная проверка, гейт, правило анализатора или условие без замены, названной в PR (охват сужен до диффа, отказ стал предупреждением, обязательное стало настраиваемым); неприменимую проверку снимает PR с причиной и способом подключить замену | блокирует |
| Второй источник истины: нарушение [SoT или DRY](CONTRIBUTING.md#13-принципы-кода) | блокирует |
| Проверка, условие которой выполняет сам проверяемый объект | блокирует |
| Факт, путь, термин или зависимость одного проекта в общем файле harness: в поставке комплекта или в установленном ею managed-файле или блоке | блокирует |
| Утверждение тела PR, которое противоречит диффу | блокирует |
| Сложность, из-за которой нельзя надежно проверить или изменить код | блокирует |
| Велосипед или костыль: нарушение [KISS](CONTRIBUTING.md#kiss) | блокирует |
| Необязательное упрощение, нейминг или более подходящий образец | советует |
| Предпочтение без правила, последствия или действующего образца | в ревью не входит |

## Что проверять

- Дизайн соответствует существующей системе и не вводит абстракцию ради одного случая.
- Основной, ошибочный и граничный сценарии дают ожидаемый наблюдаемый результат.
- Проверены права, тенант, входные данные, секреты, публичные контракты и миграции.
- Асинхронная операция проверена на стороне потребителя, а не только по `2xx` или outbox.
- Текст и комментарии проверены по [стандарту текста](docs/platform/standards/text.md) и
  [стандарту комментариев](docs/platform/standards/code-comments.md). Причина ошибки подтверждается
  кодом или данными запуска; вывод скрипта проверяется наравне с текстом автора.
- Документация меняется вместе с контрактом и не пересказывает код - [`CONTRIBUTING.md` §13, DRY](CONTRIBUTING.md#dry).

Областные правила берутся из применимого корневого skill и принятого ADR. Направление зависимостей
задают [архитектурные гейты](docs/platform/architecture/gates.md), критерии тестов - в
[standards/test-usefulness](docs/platform/standards/test-usefulness.md), комментариев - в
[standards/code-comments](docs/platform/standards/code-comments.md).

## Доказательство и форма

Ошибка поведения описывается входом, состоянием и результатом. Отступление от правила
подтверждается ссылкой на правило и, если нужен образец, на действующую реализацию. Без одного из
этих доказательств замечание в ревью не входит.

Находка привязывается к минимальному диапазону строк и содержит последствие, причину и направление
исправления. Замечание относится к коду, а не к автору. Итог не пересказывает проверенные файлы.
